Local and remote file inclusion: reading unintended files through path traversal / inclusion parameters, and when inclusion can become code execution (e.g. via log poisoning concepts).

**Key concepts to own:** LFI vs RFI; path traversal; null byte / filter issues (historical); wrappers (concept); secure file handling.

## Deep summary — section by section (original words)

**1. Intro to File Inclusions** — Apps build pages from static templates + a dynamically loaded file chosen by a parameter (`?page=`, `?language=`). If that parameter reaches an include/read function unsanitized (PHP include/require/file_get_contents; equivalents in Node/Java/.NET), the attacker chooses the file. Know each function's character: **read-only vs execute, local-only vs remote-URL** — that decides what the bug can become: disclosure → source leak → RCE. "Read-only" functions still leak source and secrets. *Use: both.*

**2. Local File Inclusion (LFI)** — Point the parameter at a local path (`/etc/passwd`, Windows boot.ini). When the code prepends a directory, absolute paths fail but `../` climbs out — extra `../` past root is harmless, so find the **minimal count** for the actual depth. A filename prefix is bypassed by starting the value with `/`; an appended extension is §3's problem. Error messages leak the exact string handed to include() — read them. And **second-order LFI**: a payload stored in the DB (e.g. as a username later used in an avatar path) fires later — developers sanitize direct input but trust their own database. *(2 Q — gap.)* *Use: both.*

**3. Basic Bypasses** — Match the bypass to the filter: non-recursive `../` removal → `....//`, `..././` (removing the middle leaves a valid `../`); blocked dots/slashes → URL-encoding (`%2e%2e%2f`) or double-encoding; "must start with ./languages/" prefix checks → start with the approved prefix, then traverse back up. Historical only (dead on modern PHP): null-byte `%00` termination and ~4096-char path truncation — know them to recognize them, don't expect them to work. Filters stack — combine bypasses. *(1 Q — gap.)* *Use: both.*

**4. PHP Filters** — The source-reading trick: `php://filter/read=convert.base64-encode/resource=<file>` returns a PHP file's **source base64-encoded** instead of executing it (a plain include of a config file shows nothing — it renders no HTML). Decode locally with `base64 -d` — copy the *whole* string or the decode truncates. Method: fuzz for other PHP pages first (ffuf/gobuster — check non-200s like 403 too), read their sources, follow references file to file until you've mapped the app and found its config/secrets. *(1 Q — gap.)* *Use: both.*

**5. PHP Wrappers** — RCE wrappers, all gated on **`allow_url_include`** (off by default — verify by reading php.ini through the LFI + base64 filter first): `data://text/plain;base64,<encoded shell>` executes the decoded code; `php://input` executes the POST body (mind GET-vs-POST — a POST-only parameter needs the command inside the code); `expect://` runs commands directly but needs the expect extension installed/enabled (an extension line in config means PHP *tries* to load it, not that it works). *(1 Q — gap.)* *Use: both.*

**6. Remote File Inclusion (RFI)** — If the function accepts remote URLs, host your shell and include it: HTTP (`python3 -m http.server` — prefer ports 80/443, more likely allowed), FTP (pyftpdlib, when HTTP is filtered), SMB on Windows (Impacket smbserver + UNC path — no allow_url_include needed). Verify first with a local URL (`http://127.0.0.1/…`) — the included page *executes*, it isn't shown as source. Almost every RFI is also an LFI; the reverse isn't true (config usually blocks remote includes). Bonus: RFI doubles as SSRF-style probing of local-only services. *(1 Q — gap.)* *Use: both.*

**7. LFI and File Uploads** — The upload form doesn't need its own bug — it just needs to *store* your file somewhere reachable. Upload a polyglot: image magic bytes (GIF8) followed by PHP code — it validates and displays as an image, but executes when included through the LFI regardless of extension. Find the stored path (page source, default upload dirs), include it, pass commands. Wrapper variants: `zip://` (zip containing a shell, referenced with `#`) and `phar://` (a phar renamed to .jpg) — powerful when enabled, often not. *(1 Q — gap.)* *Use: both.*

**8. Log Poisoning** — Any file containing your PHP code executes when included — so write code into a file the server will let you include. **Session poisoning:** the session file (`sess_<PHPSESSID>`) stores your parameter values — put the shell in the parameter, include the session file, run commands (re-poison per command; including reinitializes the session — then plant a permanent shell). **Server logs:** your User-Agent lands in access.log — poison it via Burp/cURL, then include the log (Nginx logs are often www-data-readable; Apache's usually root/adm-only; huge logs can time out). Same idea via `/proc/self/environ`, `/proc/self/fd/N`, and SSH/FTP/mail logs (poison via a crafted username or message). Read the log via LFI first to confirm access before poisoning. *(2 Q — gap.)* *Use: both.*

**9. Automated Scanning** — Fuzz for the parameter itself (forms are the tested surface; hidden parameters are the finds — Module 15's ffuf skills), then fuzz paths with an LFI wordlist (LFI-Jhaddix bundles bypasses + common files), then fuzz for the **webroot** and for log/config paths. Read the server config (`apache2.conf` → `${APACHE_LOG_DIR}` → `envvars`) to convert guesses into exact paths. Dedicated LFI tools exist but many are unmaintained Python 2 — manual technique + ffuf is the reliable kit; verify every automated hit by hand. *(1 Q — gap.)* *Use: both.*

**10. File Inclusion Prevention** — The real fix: **never let user input reach an include function** — map IDs to files server-side (DB table, case-match, static JSON) with a default for anything unmatched. Supporting layers: `basename()` (use the framework's — hand-rolled sanitizers miss edge cases), *recursive* `../` removal if you must sanitize, config hardening (allow_url_fopen/include **Off**, open_basedir or container locked to the webroot, disable expect/mod_userdir), and a WAF (ModSecurity) tuned in report-only mode first. Why it matters: traversal out of the app reaches SSH keys, other services' configs, session files (→ hijacking, Module 19), and source. Hardening buys detection time; it isn't a cure. *(2 Q — gap.)* *Use: engagement (developer-facing).*
