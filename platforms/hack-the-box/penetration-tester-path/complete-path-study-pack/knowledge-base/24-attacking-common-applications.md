Approaching the applications seen again and again on engagements — CMSs, portals, and admin tools: enumerate version and config first, then check the known issues for that exact version.

**Key concepts to own:** CMS enumeration (e.g. WordPress); plugin / theme issues; default installs and panels; version-specific research.

**The module's one methodology, applied to every product below:** discover → fingerprint version → match known issues → abuse built-in functionality (admin features, editors, deployment, script consoles) → clean up and document.

## Deep summary — by application (original words)

**1. Introduction** — Common apps (CMSs, portals, repos, monitoring, ticketing) recur in every environment, hardened in one place and wide open in another. Perimeter hardening pushes attackers toward web apps, and every app's *built-in* features are a code-execution surface, not just its CVEs. Cautionary pattern from the lesson: an exposed repository manager with default admin credentials → code execution via its own script/task feature. *Use: engagement.*

**2. Application Discovery & Enumeration** — Most organizations don't know their own inventory, so discovery finds forgotten apps, expired-trial/demo versions running without auth, defaults, and misconfigurations. Method: ping sweep → Nmap on common web ports (80, 443, 8000, 8080, 8180, 8888, 10000) → **screenshot tooling over the Nmap XML** (EyeWitness, Aquatone) to triage hundreds of hosts visually → vulnerability scanner on full-scope tests, with **manual validation of everything** — and structured per-host notes from the start. *(2 Q — gap.)* *Use: engagement.*

**3–4. WordPress** — Fingerprint via robots.txt, wp-admin→wp-login redirect, wp-content paths, plugin/theme directories; most vulns live in **plugins**, then core, then themes. Read the version from page source and plugin readme files; enumerate users from differing login error messages. Pitfall: a **child theme masks the active theme** in page source — trust the scanner's full picture. Attack: brute-force the login via **XML-RPC** (faster than wp-login; WPScan -U/-P), then admin → **Theme Editor** → edit an obscure theme file into a web shell (or MSF's plugin-upload module); vulnerable plugins give unauthenticated routes too. Clean up and report artifacts. *(3 Q, 4 Q — gap.)* *Use: both.*

**5–6. Joomla** — Fingerprints: generator meta, favicon, README.txt, media/system/js paths, administrator manifest, cache.xml; admin at /administrator; generic login errors block user enumeration (unlike WordPress). Scanners: droopescan, JoomlaScan. Attack: admin → customize a template's error page with server-side code; or CVE-2019-10945 (traversal + authenticated file deletion) when the portal isn't reachable — but never delete files on a client box. *(2 Q, 1 Q — gap.)* *Use: both.*

**7–8. Drupal** — Fingerprints: "Powered by Drupal", CHANGELOG.txt/README.txt (often removed — then modules are the surface), /node IDs, droopescan. Shell paths: **PHP Filter module** (pre-8; lets an admin page evaluate code — not installed by default on 8+), or a backdoored module uploaded via Extend. The Drupalgeddon trio: CVE-2014-3704 (pre-auth SQLi), CVE-2018-7600 (RCE), CVE-2018-7602 (authenticated RCE). Get permission before creating pages/modules; log everything for cleanup. *(1 Q, 1 Q — gap.)* *Use: both.*

**9–10. Tomcat** — Version leaks via Server header and default error pages; /docs often still installed. Know the layout: webapps, WEB-INF/web.xml, and **tomcat-users.xml** roles (manager-gui/script/jmx/status). Attack: brute-force the manager (MSF tomcat_mgr_login, Intruder) → deploy a **WAR with a JSP shell** via /manager/html → **undeploy to clean up**; or msfvenom WAR + tomcat_mgr_upload. Plus **Ghostcat CVE-2020-1938**: AJP (8009) unauthenticated file read of anything in the webroot incl. WEB-INF/web.xml. *(2 Q, 3 Q — gap.)* *Use: both.*

**11–12. Jenkins** — Port 8080 (50000 for agents). Check security config, open registration, weak/no auth — and the **service account**: Jenkins on Windows often runs as **SYSTEM**, so console access ≈ an AD foothold. Attack: **Script Console** runs arbitrary Groovy in the controller runtime → reverse shell at service privilege; several historical pre-auth/deserialization RCEs. Fix direction: auth on, registration off, least-privilege service account. *(1 Q, 1 Q — gap; §11's question prompt supplies lab login details — not copied.)* *Use: both.*

**13–14. Splunk** — Web on 8000, REST/management on 8089; often root/SYSTEM with sensitive data. The real attack surface is **weak/absent auth** (the Free edition after a trial doesn't require it): admin → package a **custom app** (bin/ scripts + default/inputs.conf) → "Install app from file" → script runs at service privilege. Scanner findings on Splunk are often false positives — validate before reporting. Deployment servers can push your app to other hosts — scope carefully. *(1 Q, 1 Q — gap.)* *Use: engagement.*

**15. PRTG Network Monitor** — Internal monitoring tool; version from the login page. CVE-2018-9276: **authenticated command injection** in notifications — Execute Program + a demo script + an unsanitized Parameter field, executed **blind** (confirm through a second channel). Defaults may fail while a weak password works — don't stop at the first failed login. On real engagements prefer a non-destructive proof over creating an admin. *(2 Q — gap.)* *Use: both.*

**16. osTicket** — Ticketing portals are credential sources, not scope filler: they hold sensitive threads, give a legitimate internal mailbox, and (lesson scenario) leak operational secrets — an agent's ticket revealed the **standard new-joiner password**, which sprayed successfully against the VPN; breach-dump credentials opened the portal itself. Also carries an SSRF (CVE-2020-24881). Fixes: MFA on external portals, strong password policy, change-after-first-login. *(1 Q — gap.)* *Use: engagement.*

**17–18. GitLab** — Repos hold committed secrets — treat instances as high-value. Version only at /help **after login**; check /explore (public projects), and **open registration** (register → internal projects). User enumeration via the sign-up form's "already taken" errors — works even when sign-up is nominally disabled. Attack: enumerate → **controlled** spray (watch lockout: defaults 10 attempts / 10-min unlock pre-16.6) → CVE-2021-22205 (ExifTool metadata RCE, CE ≤13.10.2) → shell as git. Note: GitLab doesn't count bare user enumeration as a vuln — demonstrate impact. *(2 Q, 2 Q — gap.)* *Use: both.*

**19. Tomcat CGI — CVE-2019-0232** — Windows + enableCmdLineArguments: append commands to a CGI script request with `&`. Fuzz /cgi for .cmd/.bat scripts. Environment quirk: **PATH is unset**, so bare command names silently return nothing — use full system paths, URL-encoded. A script returning nothing is not proof of safety. *(1 Q — gap.)* *Use: both.*

**20. Shellshock — CVE-2014-6271** — Old Bash imported functions from environment variables and executed trailing commands; any CGI field/header (classically User-Agent) becomes code execution as the web account. Find a CGI script (Gobuster), test with a function-definition probe, then the reverse-shell form. Still found in the wild — never dismiss a flaw for being old. EOL systems: isolate or decommission; firewalling is a stopgap. *(1 Q — gap.)* *Use: both.*

**21–22. Thick Client Applications** — Locally installed clients (Java/.NET/C++) carry secrets **inside the binary**: hardcoded credentials, connection strings, service tokens. Attack all three tiers: client (decompile/debug — Ghidra, dnSpy, x64dbg, Frida), network (Wireshark, proxies), server (treat like a web app). Lesson scenario: a "does-nothing" executable traced with Process Monitor to a temp batch file — preserve the temp folder (make it non-deletable) before it self-cleans, dump the dropped payload from memory, decompile → a run-as tool with **hardcoded service credentials**. §22: three-tier clients still carry web flaws — patch a signed client JAR (strip manifest hashes/signatures, rebuild) to bypass a path filter, traverse to the server JAR, find the unsanitized login query, and beat the password-hash trap (the server hashes username+password+salt, so a naive injection mismatches — the UNION-fabricated row must carry the password itself). *(1 Q, 1 Q — gap.)* *Use: both.*

**23–24. ColdFusion** — Fingerprint: .cfm/.cfc extensions, headers, errors, admin at /CFIDE/administrator, and non-standard ports (8500, 5500…) — a port list is a starting point, not a boundary. Attack (old versions): CVE-2010-2861 traversal via the locale parameter reads the encrypted-password store; CVE-2009-2265 unauthenticated editor upload → shell. Confirm the version before firing version-specific exploits. *(1 Q, 1 Q — gap.)* *Use: both.*

**25. IIS Tilde Enumeration** — Windows 8.3 short names: `~1` addressing plus per-character responses leak hidden file/dir names letter by letter (IIS ShortName Scanner); build a candidate wordlist from the short-name matches and Gobuster the full name — some files then need a non-GET method. Fix: disable short-name generation; obscurity is not a control. *(1 Q — gap.)* *Use: both.*

**26. Attacking LDAP** — LDAP (389/636) is a **protocol**, not a directory — AD is a service that uses it. No encryption by default. Injection: user input inside a search filter bends with wildcards/grouping characters (`* ( ) | &`) — wildcards in both login fields made an always-true match and bypassed auth. Fix: parameterized queries, input sanitization, LDAPS/StartTLS. *(1 Q — gap.)* *Use: both.*

**27. Web Mass Assignment** — Frameworks that bind whole form payloads to objects let attackers set **fields the form never showed** — the lesson's app had a confirmation parameter that skipped admin approval: register, intercept in Burp, add the parameter, log in. Source review finds the parameter names. Fix: explicit allowlist assignment of attributes. *(1 Q — gap.)* *Use: both.*

**28. Attacking Applications Connecting to Services** — Binaries embed **connection strings**: ELF → GDB/PEDA, follow calls from main to the string, breakpoint, read it; .NET DLL → dnSpy straight to the controller's connection string. The recovered credential rarely belongs to one service — try it laterally (and spray carefully). Fix: secrets in a vault, never in binaries; least-privilege service accounts; rotation. *(1 Q — gap.)* *Use: engagement.*

**29. Other Notable Applications** — The methodology transfers; the survey names the usual suspects and their recurring shapes: Axis2 (AAR service upload ≈ Tomcat WAR), WebSphere (console → WAR deploy), Elasticsearch (forgotten installs), Zabbix (SQLi/auth bypass/API → code execution), Nagios (defaults + version issues), WebLogic (deserialization RCE history), wikis/intranets/SharePoint, DotNetNuke (auth bypass, traversal, upload bypass), vCenter (incl. CVE-2021-22005 OVA upload). Discipline: dig through scan noise instead of walking away when nothing is *obviously* exploitable. *(2 Q — gap.)* *Use: engagement.*

**30. Application Hardening** — You can't protect what you don't know exists: maintain the inventory (Nmap + EyeWitness on a budget), then per-app: change/disable default admin accounts, custom admin usernames, MFA for admins, no external login pages without a business reason, deny upload/deploy permissions, disable dangerous features (WordPress PHP editing), patch promptly, back up site + database, monitor (Wordfence, AdminExile, Jenkins Matrix Authorization), SSO/LDAP integration. Watch for **trial→free downgrades that silently drop authentication** (the Splunk pattern). *(Theory.)* *Use: engagement.*

**31–33. Skills Assessments I–III (scenarios)** — I: one hardened-looking host, full discovery→foothold chain — the interesting host is the one you'd dismiss. II: iterative vhost chaining (WordPress → public GitLab project → a third vhost's app → admin → shell) — won by **re-reading your own enumeration notes** after dead ends. III: §28 applied — extract a hardcoded MSSQL password from a .NET assembly with dnSpy. *(11 Q total — gap; scenario text only; prompts' login details not copied.)* *Use: both/engagement.*
