## Deep summary (original words)

**1. Intro** — The capstone's premise: the path taught skills in isolation (27 modules, seven mini-tests, 200+ targets, one fictional client); here they interleave — recon → web → network → recon again → AD → privesc → pillage → lateral movement — and the skill being tested is *switching* between them without a script. *Use: engagement.*

**2. Scenario & Kickoff** — Before any packet: SoW + signed **RoE** (the authorization to test), scope pinned (external ranges and domain; internal ranges; explicitly out: phishing, physical, DoS/destructive, changes without written consent), two named contacts per side, testing window, heavy scanning outside business hours, start-of-testing email sent, VM + skeleton notes + report template set up first. One week of testing, two days to draft. *Use: engagement.*

**3. External Information Gathering** — Breadth then depth: quick top-1000 Nmap → full-port with version/script detection (care: scripts can disrupt services) → parse output into a service list with a text pipeline → **dig axfr** (succeeds here: nine more subdomains) with passive fallbacks if refused → **ffuf vhost fuzzing** with a known-invalid baseline size (one vhost the zone transfer missed). Everything saved to the project tree; names into /etc/hosts. *(4 Q — gap.)* *Use: both.*

**4. Service Enumeration & Exploitation** — Probe every service and *record the dead ends as findings*: FTP anonymous (read-only, one file), SSH current (a few default pairs, no luck), SMTP **VRFY enabled** (Low — user enumeration; open-relay check negative), POP3/IMAP nothing, **rpcbind exposed externally** (Low — unnecessary surface). An open port is not a vulnerability; an unnecessary exposed service is a finding. Don't chase out-of-scope DoS proofs. *(1 Q — gap.)* *Use: engagement.*

**5. Web Enumeration & Exploitation** — The biggest external surface, worked app by app (EyeWitness screenshots first) — and note the scope discipline: an external pentest samples web apps for high-risk issues; it is not a full web assessment. The harvest, one flaw class per app: careers portal **IDOR** (other users' data); dev "Key Vault" — directory listing + **TRACK verb tampering** past a custom header check + client-side type validation bypassed → upload → **RCE**; WordPress — WPScan enum + **weak admin password** → theme-editor shell; status app — **error-based SQLi** → sqlmap dump; support — **blind XSS** → admin cookie exfiltrated; tracking — PDF HTML injection → **SSRF to local file read**; GitLab — open registration + /explore intel; shop app — weak login → **XXE** file read; monitoring — brute-forced login → restricted shell → **command injection** (newline beats the blocked `;`/`|`; quoting beats the blocked word) on a host with an internal IP = **the pivot**. Dead ends (blog defaults, VPN) logged; test accounts removed at closeout; the "unexpected" handled by research → adapt → or note as needs-further-research. *(9 Q — gap.)* *Use: both.*

**6. Initial Access** — RCE is not a shell: pass a **Socat reverse shell** through the filtered injection point (same bypasses as §5), catch it, then upgrade with a Socat full-duplex tty listener so su/sudo/editors behave. Then local enum pays immediately: the web user is in **adm** → /var/log readable → audit logs show a service admin's authentication → su across. Stabilize *before* going deeper. *(1 Q — gap.)* *Use: both.*

**7. Post-Exploitation Persistence** — Build the save point: SSH in with the found credentials; keep a **backup route** (the original injection re-arms a shell, or Meterpreter) in case the account is burned; then `sudo -l` → openssl as root → **GTFOBins file-read of root's SSH private key** → key saved locally (chmod 600) → root SSH = fast return + pivot base. Document every persistence method you plant. *(1 Q — gap.)* *Use: engagement.*

**8. Internal Information Gathering** — Through the pivot (SSH -D + ProxyChains, or Meterpreter autoroute): ping-sweep the internal range → DC, a Windows web/NFS host, a Tomcat host. Work the dead ends honestly (SMB null session denied — spraying/AS-REP noted as next options; Tomcat manager brute force fails) and the live one: **NFS share open to everyone** (mount it from the DMZ host — NFS won't ride ProxyChains) → web.config → the application admin credential. Parallel enumeration; dead ends logged. *(1 Q — gap.)* *Use: engagement.*

**9. Exploitation & Privilege Escalation** — App admin → host SYSTEM → domain credential: log in as SuperUser (two distinct findings recorded: **Insecure File Shares** and **Sensitive Data on File Shares** — anonymous access and Domain-User overexposure are different problems); SQL console with **xp_cmdshell** for OS commands as the service account (or an .aspx shell via allowed extensions); **PrintSpoofer** on SeImpersonate → SYSTEM; `reg save` the SAM/SECURITY/SYSTEM hives → secretsdump → local hashes + cached logons + LSA secrets; pass-the-hash validates the local admin; among the recovered material sits the **first domain credential**, verified against the domain. System changes (e.g. sshd GatewayPorts for an alternate tunnel) need client clearance, a note, and a revert. *(2 Q — gap.)* *Use: engagement.*

**10. Lateral Movement** — Identity-chaining, iterated *per user*: SharpHound/BloodHound shows a force-password-change right over another user + all Domain Users holding RDP on a dev box (finding: **Excessive AD Group Privileges**); RDP via ssh -L with drive redirection for tool transfer; PowerView executes the reset. Re-run share hunting as **each new identity** (spider_plus): a backup script in an IT share holds a hardcoded service credential (keyboard-walk pattern — an org trend worth its own note), SYSVOL holds a legacy script credential. Kerberoast everything (one crack, not useful — finding: **Weak Kerberos Authentication**); spray within policy (two more users — finding: **Weak AD Passwords Allowed**); sweep the odd corners — GPP autologon (empty), **passwords in AD description fields** (one found). On the next host: WinRM in, an **unattend.xml** credential (RDP but not admin), a SYSTEM scheduled-task service whose watched folder grants Administrators on file creation, then pillage (budget spreadsheet, a password database) and an LSA dump yielding the SQL admin credential that unlocks §11. *(4 Q — gap.)* *Use: engagement.*

**11. Active Directory Compromise** — The delegation chain snaps shut: the SQL admin has **GenericWrite** over a user → plant a **fake SPN** on that account (PowerView) → targeted Kerberoast → offline crack → that user holds **GenericAll over a group that itself holds DCSync rights** → add the user → **secretsdump -just-dc-ntlm** = the domain. Aftermath discipline: delete the fake SPN, log every account change in the appendices, crack the full NTDS offline for the password-strength story, and evidence DC access readably (hostname/whoami/ipconfig screenshots) — a hash dump alone doesn't persuade a client. *(3 Q — gap.)* *Use: engagement.*

**12. Post-Exploitation** — DA is a means: **DPAT** on the cracked NTDS (percent cracked, top passwords, length spread, DA/EA hits) for the appendices; **PingCastle** posture audit; sensitive-data hunting in shares *without opening or removing PII* (and DA's blanket data access is itself a finding). Then test segmentation: SSH keys in an IT share + the DC's second NIC → a live host on the management range → **double pivot** (attack box → DMZ → DC → target; Meterpreter + autoroute + SOCKS) → key-based SSH in → **Dirty Pipe** against a SUID binary → root → **clean up the exploit files**. Value after DA is reputation: real analysis, no padded findings. *(2 Q — gap.)* *Use: engagement.*

**13. Engagement Closeout** — End clean or the report doesn't count: testing-completed email with the draft date + review-meeting request (worst findings never debut *in* the report); findings ordered by risk — the example summary runs nine Highs (command injection, unrestricted upload, LFI, weak/default password, weak AD password policy, insecure shares, sensitive data on shares, weak Kerberos config, password in a description field) + one Medium (excessive group privileges); the **attack path of least resistance** written out end to end; **cleanup total** — every tool, shell, payload, account and change removed or restored and itemized in the appendices; logs retained for the client's alert correlation; internal closeout (archive, lessons learned, retest agreed, original tester does the retest if possible). *(Theory.)* *Use: engagement.*

**14. Beyond this Module** — After the path: build a **concept review list** of everything shaky and re-drill it (Global Search finds the sections); move to the main platform — Starting Point tiers → a Track aimed at a weak spot → **Pro Labs** for unguided realism; give back (help channels, write-ups, a blog) because teaching is consolidation; and treat the soft skills as part of the craft — communication, writing, teamwork, ethics — while the job search runs (Talent Search, boards, conferences, community). Finishing the path is a milestone, not a finish line. *(Theory.)* *Use: both.*
